== Explore Detected CVEs

Before wiring up any automation, review what Satellite already knows
about. `rhel1.lab` and `rhel2.lab` were seeded with a handful of
deliberately vulnerable packages during lab setup. Both have already
reported their installed packages back to Satellite via `insights-client`.
Satellite cross-references that against Red Hat's published CVE data to
identify which hosts are affected by which CVEs. Neither host leaves the
lab network.

For details on the seeded vulnerabilities, https://github.com/rhpds/zt-satellite-lightspeed-ansible/blob/8975dbe9d64379f217d4555188740e3d79037f56/setup-automation/setup-satellite.sh#L77[see this section of the lab setup script].

======
First, open the Vulnerability dashboard.

.Step 1 - Open the Vulnerability dashboard
[%collapsible]
=====
Click on the tab labelled `Satellite Web UI` (log in with the same
credentials from Module 1, if you are not already).

In the left navigation, go to *Red Hat Lightspeed -> Vulnerability*.

.Vulnerability menu
image::vulnerability-service-menu-bar.png[]

This page is powered by Satellite's own, on-premises-hosted Red Hat
Lightspeed Vulnerability service. Despite the similar name, it is not
the same as the `console.redhat.com` cloud dashboard. Everything shown
here comes from CVE data that was already synced into Satellite during
lab setup, cross-referenced against each host's package list. No data
leaves the Satellite server.
=====
======

======
Next, review the CVEs Satellite has already detected.

.Step 2 - Review the detected CVEs
[%collapsible]
=====
You should see a list of CVEs affecting your managed hosts, each with a
severity rating (Critical/Important/Moderate/Low), a CVSS score, and a
count of how many systems it affects.

.Vulnerability dashboard
image::vulnerabilities-dashboard.png[]

Sort or filter by *Severity* to see the most impactful CVEs first. Note
a few things as you browse the list:

.Vulnerabilities sort button
image::vulnerabilities-sort.png[]

The *Systems Affected* count links through to exactly which hosts
(`rhel1.lab`, `rhel2.lab`, or both) are impacted by each CVE.

.Systems affected
image:vulnerabilities-systems-affected.png[]

Not every CVE has a fix available yet in Satellite. A CVE becomes
actionable only once Satellite has synced an erratum (patch) that
resolves it.

=====
======

=======
Finally, drill into one CVE to see exactly what fixes it.

.Step 3 - Drill into one CVE's details
[%collapsible]
======
Click into any CVE affecting 2 systems.

.Click into a CVE
image::vulnerabilities-affected.png[]

The detail page shows:

- The full CVE description and CVSS score
- Which hosts are affected
