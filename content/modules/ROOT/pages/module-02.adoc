== Explore Detected CVEs

Before wiring up any automation, let's look at what Satellite already
knows about. `rhel1.lab` and `rhel2.lab` were seeded with a handful of
deliberately vulnerable packages during lab setup and have already
reported their installed packages back to Satellite via `insights-client`.
Satellite cross-references that against Red Hat's published CVE data to
tell you exactly which hosts are affected by which CVEs - without
either host ever leaving the lab network.

======
First, let's open the Vulnerability dashboard.

.Step 1 - Open the Vulnerability dashboard
[%collapsible]
=====
Click on the tab labelled `Satellite Web UI` (log in with the same
credentials from Module 1, if you aren't already).

In the left navigation, go to *Red Hat Lightspeed -> Vulnerability*.

.Vulnerability menu
image::vulnerability-service-menu-bar.png[]

This page is powered by Satellite's own, on-premises-hosted Red Hat
Lightspeed Vulnerability service. Despite the similar name, it's not
the same as the `console.redhat.com` cloud dashboard. Everything you
see here comes from CVE/vulnerability data that was already synced into
Satellite during lab setup, cross-referenced against each host's
package list. As well, no data leaves the Satellite server.
=====
======

======
Next, we'll review the CVEs Satellite has already detected.

.Step 2 - Review the detected CVEs
[%collapsible]
=====
You should see a list of CVEs affecting your managed hosts, each with a
severity rating (Critical/Important/Moderate/Low), a CVSS score, and a
count of how many systems it affects.

.Vulnerability dashboard
image::vulnerabilities-dashboard.png[]

Sort or filter by *Severity* to see the most impactful CVEs first. Note
a few things as you browse the list:

.Vulnerabilities sort button
image::vulnerabilities-sort.png[]

- The *Systems Affected* count links through to exactly which hosts
  (`rhel1.lab`, `rhel2.lab`, or both) are impacted by each CVE.
- Not every CVE necessarily has a fix available *yet* in Satellite - a
  CVE only becomes actionable once Satellite has synced an erratum
  (patch) that resolves it.

.Systems affected
image:vulnerabilities-systems-affected.png[]

=====
